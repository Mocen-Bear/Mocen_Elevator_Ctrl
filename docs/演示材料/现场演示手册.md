# 现场演示手册（开赛前照着走）

> 这是**给自己人看的**操作手册，不是给队友的接口文档。
> 目标：**把演示失败的概率压到接近 0**；真出问题时有**明确的下一步**，不现场发呆。

---

## 0. 一句话

能不能炸场，取决于两件事：**① 装置真的按下去了**，**② 电梯真的来了**。
前者我们 100% 可控（自己装的）；后者不可控（电梯是别人的）。
所以手册的重点是：**把①做到万无一失，并给②准备一个体面的退路。**

---

## 1. 出发前一晚 · 清单

- [ ] **先跑一次体检脚本**（一条命令，会逐项告诉你哪里没对上）：
      ```powershell
      cd "D:\文档\Default Project\elevator-control"
      powershell -ExecutionPolicy Bypass -File .\preflight.ps1
      ```
      它会检查：预览页在不在 / **每个资料包的 zip 和文件夹是不是逐字节一致** /
      **主包的 3 份文件还是不是和源文件同一个哈希** / **APK 是不是比源码旧**（这个坑真的踩过）/
      固件的楼层名·D13上行·D12下行·350/600ms 有没有被改错 / **全仓库有没有残留 `ELEV-1F`**。
      想要连编译一起验就加 `-Compile`（慢一点）。**全绿了再出门。**
- [ ] **烧固件**（两块板，别烧错）
      `elevator_2F/elevator_2F.ino` → 2F 的板子；`elevator_3F/elevator_3F.ino` → 3F 的板子。
      分区选 **Huge APP (3MB No OTA/1MB SPIFFS)**；串口 115200。
      ⚠️ **烧之前先拔掉 D12 上的舵机信号线**（GPIO12 是 strapping 脚，会挡住烧录）。
- [ ] **手机装 App**：仓库里 **`安卓App/电梯呼叫_v10.apk`**（就是 v10 这份；**别再装 v9 或更早的**）。
      装完**打开一次**确认能扫到 `ELEV-2F` / `ELEV-3F`。（v10 起 App 里**没有语音**了 —— 真机上识别不准，已删。）
- [ ] **舵机供电**：舵机 VCC 走**外部 5V**（充电宝 + 5V 升压 / 5V 电源），**严禁**接 ESP32 的 3V3。
      GND 必须和 ESP32 **共地**。
- [ ] **固定件**：美纹纸胶带 / 扎带 / 泡棉胶 —— 到场要能把舵机臂**对准**呼梯按钮。
- [ ] **充电宝**：ESP32 + 舵机共用一个 5V，能连续跑 1 小时以上。
- [ ] **【重要】拍一张大厅楼层显示的照片**（手机对着呼梯面板/门上方拍）。
      要看清楚：**有没有数字楼层显示？数字在照片里大概多少像素宽？**
      - 有数字、≥20 px → 摄像头方案（`preview/floor_display_reader.html`）可用；
      - 只有 ▲▼ 灯、没数字 → **摄像头方案直接放弃**，用"模拟 + 标注"。
- [ ] **下载/收藏整个 `preview/` 目录**（离线也能开；**页数以 `index.html` 演示台为准，它会自动数**）。**上台按这个顺序用**：
      `index.html`（**演示台**，迷路时看它）→ `deck.html`（**11 页幻灯片**，路上讲的骨架）→
      `storyboard.html`（30 秒演出，**保险**，见 §4）→ `elevator_3d_preview.html`（3D 井道）→
      `elevator_ui_preview.html`（按钮/面板界面）→ `rssi_floor_sim.html`（**判定调参器**，见 §2 第 5 步）→
      `floor_display_reader.html`（摄像头读楼层显示，配上面那张照片）→
      `chime_calib.html`（**到站"叮"声标定台**，只在装到站检测节点时才用）→
      `ble_console.html`（**现场蓝牙控制台**，只在手机 App 扫不到装置时救场，见 §4 对照表）。
- [ ] **（可选，装了"到站检测"节点才需要）** 带上麦克风模块（MAX9814 等）+ 一个 10~47µF 电容。
      到场后打开 `preview/chime_calib.html`，让它听几次**真实的"叮"**，把右下角给出的 `#define` 那几行
      抄回 `firmware/chime_node/chime_node.ino` 再重烧。**不装这块节点就整条跳过** —— 主包不装它也能完整演示。
- [ ] **（可选，能解锁两个功能）** 如果要从**笔记本**上用浏览器调摄像头/蓝牙：
      把 `http://<你的局域网IP>:8777` 加进 Chrome 的
      `chrome://flags/#unsafely-treat-insecure-origin-as-secure`（"Insecure origins treated as secure"），
      否则 `http://` 下 **摄像头（getUserMedia）和 Web 蓝牙都会被浏览器拦掉**（localhost 不受影响）。
      演示当天**不要**依赖这个设置；只用它来提前试。
      （Web 蓝牙那条对应的是 `preview/ble_console.html` —— 手机 App 扫不到装置时用它顶上。）

## 2. 到场后 10 分钟 · 落地

1. **贴装置**：舵机臂对准按钮，手动试一次按压行程（松 → 按到底），确认按钮能被压下去。
2. **通电**：看板上 LED / 串口是否正常启动，BLE 广播出 `ELEV-2F` / `ELEV-3F`。
3. **手机点一次 UP**： Confirm ①舵机动了 ②呼梯灯亮了 ③手机收到 `2F|OK:UP`。
4. **记 RSSI**：站在 2F 门口看 App 显示的 dBm；走到 3F 再看。
   两者差 **≥ 8 dB** 才稳。差得少 → 把装置贴得离门口更近一点，或换位置。
5. **抖不抖**：在两层之间来回走，看楼层数字会不会乱跳。
   会抖 → **记下当时的 dBm**，演示时站位避开那个位置；
   想更狠一点：打开 `preview/rssi_floor_sim.html`，把 `minLeadDb` / `winCount` 拖到现场参数下复现一次，
   选一个"不抖"的组合（推荐 4.5 dB / 连赢 2），再照着改 App 里的默认值。

## 3. 演示脚本（3 分钟版）

| 时间 | 你做什么 | 你说什么 |
|---|---|---|
| 0:00 | 站在 2F 门口，掏出手机 | "我们现在在电梯厅。**我们不碰任何公共按钮。**" |
| 0:15 | 手机 App 上"2F 上行"按钮自动浮现 | "手机靠 BLE 信号强度就知道我在 2F、离井道多近 —— **按钮自己浮出来**。" |
| 0:25 | 点一下按钮 | "点一下就行。" |
| 0:30 | 指墙上：舵机动、灯亮 | "**看，舵机真的把电梯的按钮按下去了**，呼梯灯亮。" |
| 0:40 | 手机收到回执 | "回执 `2F|OK:UP` —— 这表示**我的动作完成了**。" |
| 0:50 | 打开井道透视 | "抬头看：**井道就是叠在走廊上的**，这就是电梯井。" |
| 1:00 | 轿厢动画下来 → 到站 | "轿厢从 4F 下来，到 2F。"（**如果是模拟，主动说"这里的位置是模拟的"**） |
| 1:20 | 在 App 里点 ▲ / ▼（或 2F 楼层键）再呼一次 | "呼梯永远是「**你所在那一层**」的按钮，去哪层只用来决定上/下。同一套逻辑：点悬浮钮、点 ▲▼、或者队友导航 App 走接口，结果一模一样。" |
| 1:40 | 收尾 | "**呼梯是真的；位置我们没装传感器前不假装。**" |

> **主动说"模拟"= 加分，不是减分。** 换一个说法："位置我们现在是模拟的，但我们已经把两条真实位置的路写好了：
> 一个挂在井道边听电梯到站的叮声，一个是摄像头读电梯自己的楼层显示（实测 84~89% 读对）。"

## 4. 出问题怎么办（**照这个表走**）

| 症状 | 先查 | 还不行 |
|---|---|---|
| 舵机不动 | 舵机 5V 有没有？GND 共地没有？D12 是不是被烧录时拔了没插回？ | 换成手动按一下按钮，只演示"手机浮出按钮 + 井道透视" |
| 手机扫不到 `ELEV-*` | 板子是不是还在广播（串口打印）？关掉再打开手机蓝牙；重启板子 | 换第二台手机；还不行就**用笔记本 Chrome 开 `preview/ble_console.html`**（需先按 §1 那步放行 Web 蓝牙），选中 `ELEV-2F` 直接点 `UP`/`DOWN` —— 一样能当场演出"手指一动、舵机真的按下" |
| 楼层数字乱跳 | 站远/站近 30 cm 再看；避开两层中间 | 用 `preview/rssi_floor_sim.html` 现场选参数：把 `minLeadDb` 提到 4~5 或 `winCount` 改成 2（仿真里中间位置的横跳从 25.7 次降到 1.3 次） |
| 电梯半天不来 | 别干等 | **改演"按下 → 灯亮 → 回执"**，轿厢说"我们用模拟演示行进" |
| App 崩了 / 手机没电 | — | 开 `preview/elevator_3d_preview.html` 或 `elevator_ui_preview.html` 顶上 |
| **什么都跑不起来** | — | ⭐ **开 `preview/storyboard.html`，点「放映模式」（或按 F）**：<br>30 秒把"走近→按钮浮出→点按→舵机按下→灯亮→井道→轿厢→到站→门开→再按一次下行"全部演完。<br>这是**录屏级**的保险，不用任何硬件。 |

## 5. 对方可能问的问题 · 标准答案

| 问题 | 回答（要点） |
|---|---|
| 你怎么知道电梯在 3F？ | **"现有硬件测不出来，我们不假装。"** 然后给出两条真路：听叮声的固件（已写好）、摄像头读楼层显示（实测 84~89%）。**没装之前，UI 上标了"模拟"。** |
| 你们有电梯的授权吗？ | 没有，也没有控制电梯系统的接口。我们做的是**厅外呼梯**（等价于一个人伸手按按钮）。**没有安全风险**（不会开车门、不会改电梯逻辑）。 |
| 装这个合法吗？ | 我们只**按压**公共呼叫按钮，不改电梯任何电气连接。演示用的装置可以 10 秒拆下。 |
| 为什么不用 Wi-Fi / 蓝牙配对？ | BLE 广播**不用配对、不用连接**就能拿到 RSSI，判定是**瞬时**的（真机 **40~200 ms**：扫到新广播就重判、节流 40 ms，200 ms 心跳兜底）。连接只在按下的那一刻建立。 |
| 多个人同时用会怎样？ | 一台 ESP32 最多同时服务 3 台手机，回执是**广播**的（notify），谁都能看到状态。 |
| **它会不会自己乱按？**（安全题，一定要背熟） | **不会，可以指着代码讲**：全工程只有 **2 个能真正发命令的入口**（▲/▼ 按钮、HTTP 接口；**App 里那个语音入口 v10 已删**）；**判定/信号回调里一行呼梯代码都没有**（只有 `moveCarTo()` 把轿厢挪过去，纯视觉）。另外 **1F/4F 没有装置，手动选了也只会被拒绝**。 |
| 井道是怎么"透视"的？ | 半透明发光线框 + 真实几何（尺寸、配色和安卓端、`SHAFT_MODEL.md` 完全一致）。**ARKit 默认没有遮挡，所以是"透视光绘"风格**，我们主动选择这个风格。 |
| 楼层数字会不会在两层之间乱跳？ | 不会，而且**可以当场证明**：`preview/rssi_floor_sim.html` 把 App 里的判定算法逐行搬进网页跑仿真。站在某层装置旁 20 s **0 次抖动**（首判 200 ms）；站在两层**正中间**朴素做法 20 s 横跳 **25.7 次**，我们 **4.3 次**，换成推荐现场参数只剩 **1.3 次**。<br>**被追问"到底几毫秒"时的口径**：仿真**故意按最保守的 200 ms 采样**；真机里每扫到一次新广播就立刻重判（`BleManager.kt` 节流 **40 ms**）+ 200 ms 心跳兜底，所以真机是 **40~200 ms** —— **两个数字都对**，别慌。 |
| 摄像头读数准吗？ | 单帧 84~89% 读对、0~2% 读错，其余输出"未识别"；**实时模式要求连续 3 帧一致才采纳**。宁可说"没看清"，也不猜。 |
| 这套东西的边界在哪？ | 见 `能力与边界.md`：**能做的 10 条 + 明确不能做的 5 条**，每条都写了证据在哪。 |

## 6. 演示前 60 秒的"最后一分钟"检查

```

[ ] 点一次 UP：舵机真的动、灯真的亮（这一步一定要在下楼之前做！）
[ ] 手机亮度拉满（呼梯按钮要看得到）
[ ] storyboard.html 已经在浏览器里开着（保险）
[ ] 井道页面已经开着（别现场找文件）
```
