# 术语表

项目里反复出现、但文档之间叫法不统一的词，在这里统一。

## 空间与物理

| 术语 | 含义 |
|---|---|
| **井道** | 电梯运行的竖直通道。本项目固定为 **井道 B**，楼层 **1F / 2F / 3F** |
| **轿厢** | 电梯的载人箱体。界面上画两个轿厢（双梯），但演示只跑一台 |
| **呼梯** | 请求电梯到某一层、并指定上行或下行（`UP` / `DOWN`） |
| **呼梯板 / 呼梯节点** | 贴在墙面按钮旁的自制设备，由 ESP32 + 舵机 + 增压结构件组成 |
| **增压装置** | 机械结构部分：用曲柄滑块把舵机的旋转变成对实体按钮的按压 |
| **到站叮声** | 可选节点 `chime_node`，在轿厢到站时发声，不装也能完整演示 |

## 蓝牙与协议

| 术语 | 含义 |
|---|---|
| **广播名** | 设备对外显示的名字，本项目为 `ELEV-1F` / `ELEV-2F`，App 按前缀 `ELEV-` 过滤 |
| **GATT** | BLE 的数据组织方式：服务（Service）下挂特征（Characteristic） |
| **服务 / 特征** | 本项目服务 `FFE0`；特征 `FFE1` 收命令，`FFE2` 回状态 |
| **write** | 手机往 `FFE1` 写 `UP` / `DOWN`，是**唯一**的触发方式 |
| **notify** | `FFE2` 主动推送回执，形如 `1F|OK:UP` |
| **手动呼梯** | 只有用户主动点按才下发指令；**没有任何自动触发**，这是设计红线 |

## 楼层判断

| 术语 | 含义 |
|---|---|
| **判层** | 用蓝牙信号强度推断手机在哪一层 |
| **RSSI** | 接收信号强度指示，判层的原始输入，抖得厉害 |
| **中位数滤波** | 取一串 RSSI 的中位数，先干掉个别异常值 |
| **EMA** | 指数移动平均，让曲线更平滑、更跟手 |
| **滞回** | 上、下阈值的设定不对称，避免在边界反复跳层 |
| **连胜防抖** | 连续 N 次得出同一结论才真正切换楼层 |

## 构建与交付

| 术语 | 含义 |
|---|---|
| **合并镜像** | 已把 bootloader、分区表、应用本体拼好的 `.bin`，按地址直接烧即可 |
| **预编译包** | `releases/` 下现成的 APK / bin，不需要自己构建 |
| **交接包** | `packages/` 下按接收方拆好的独立文档包，可单独发送 |
| **自检脚本** | `tools/preflight.ps1`，改动后跑一遍：目录与关键文件、固件/App 楼层常量、旧楼层残留、文档链接 |
| **原型页** | `preview/` 下的静态 HTML，不编译、不开服务器，双击即看 |
