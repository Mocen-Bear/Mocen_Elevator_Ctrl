## 三、项目简介与功能说明

### 3.1 项目简介（300 字以内，可直接粘贴用）

> 在电梯厅外，人要做的事只有一件：**按一下呼梯按钮**。但对提着重物、抱着孩子、
> 或者暂时腾不出手的人来说，这一下并不轻松，也不卫生。
>
> 我们做了一套**零改造**的呼梯装置：手机 App 打开即自动扫描，用**蓝牙广播信号的强弱**
> 判断"你正站在哪一层、离井道多近"，然后把该层电梯的**真实呼梯按钮**用舵机按下去。
> 装置通身只有一个"贴在墙上"的 3D 打印支架 + 一块 ESP32 + 一个舵机，**不碰电梯任何线路**、
> **10 秒可拆**，全部**离线可用**、**零预算**。
>
> 关键是**我们不自称能做到做不到的事**：我们只按公共按钮、不控制电梯；
> 收到 `2F|OK:UP` 只代表"舵机动作完成"，**不代表轿厢动了**。
> 凡是我们测不到的（轿厢真实位置、还有几秒到），界面上要么不显示，要么明确标注来源。

### 3.2 功能说明（按"用户看到什么"写）

| # | 功能 | 用户看到 / 体验到什么 | 技术上是怎么做出来的 |
|---|---|---|---|
| 1 | **打开即用** | 打开 App 就开始工作，**不用配对、不用扫码、不用点"开始搜索"** | 手机持续扫描 BLE 广播（不建立连接），每扫到一次新广播就立刻重判，节流 40 ms |
| 2 | **自动认楼层** | 顶部层显自动变成"你所在楼层"（2F / 3F），3D 井道里对应楼层高亮 | 按 RSSI 强弱 + 中位数窗口 + EMA + 3 dB 滞回 + 连赢计数，四道防抖 |
| 3 | **隔空呼梯** | 点 **▲ 上行 / ▼ 下行**，该层的真按钮被**真的按下去** | 手机 → BLE 写 `UP`/`DOWN` → 该层 ESP32 → D13/D12 出 50 Hz PWM → 舵机转 22° 压按钮 |
| 4 | **真回执** | 界面提示 `2F \| OK:UP`（表示**舵机动作完成**） | ESP32 通过 Notify 特征**广播**回执，所有已订阅的手机都能收到 |
| 5 | **多人同时用** | 一块 ESP32 最多 **3 台手机**同时连接、各自控制，互不影响 | 固件 v5 起：断开一台不影响其它手机收通知 |
| 6 | **看得见的 3D 井道** | 可手指拖动旋转的 1F–4F 电梯井；轿厢会动，到站自动开门；**只有 2F/3F 画全**，1F/4F 是半透明虚影 | 安卓端软件渲染（自写投影 + painter 排序），几何常量与规格页逐条对齐 |
| 7 | **两台电梯** | 甲梯**跟着你**（你在哪层它就在哪层），乙梯**随机跑**（纯装饰） | 乙梯的随机**只发生在界面里**，接口里 `car2` 恒为 `null`（不知道就说不知道） |
| 8 | **给队友 App 的接口** | 队友的 iOS 导航 App 直接 HTTP 调 `/api/call?floor=2F&dir=UP` | 安卓端内置 `LocalApiServer`（8899），和点按钮**走同一条代码路径** |
| 9 | **安全红线（写进代码里的）** | 永远不会"自己乱按" | ① 全工程只有 **2 个**能发命令的入口（▲/▼ 按钮、HTTP 接口）；② 信号/判定回调里**一行发命令的代码都没有**；③ `tryCall()` 第一句就拒绝 1F/4F；④ 换楼层只改 UI，从不自动呼梯 |

### 3.3 我们**明确做不到**的（主动写在最前面，也是设计的一部分）

| 做不到 | 为什么 | 我们怎么处理 |
|---|---|---|
| 测不出轿厢真实在哪层 | 两块 ESP32 只会"按按钮"，电梯不给我们任何反馈 | 界面**永远标来源**；没装传感器时明确是"蓝牙判层/模拟" |
| 控制不了电梯 | 没有授权、也没有接口 | 我们只做**厅外呼梯**，等于把"有人伸手按一下"自动化 |
| 不知道还有几秒到 | 同上 | **不显示**这类假数据 |
| 现场没有网络也 OK | —— | App 全程 BLE，不需要服务器；网页预览全是本地文件 |
