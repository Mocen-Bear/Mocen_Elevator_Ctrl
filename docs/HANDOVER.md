# 交接说明：把「靠近电梯 → 悬浮呼梯按钮」做进 iOS 导航 App

> 给谁看：**你的 iOS 导航 App 队友**（以及他用的 AI agent）。
> 你（硬件/安卓这边）不用他碰任何硬件——**板子已经烧好、装置装在 1F/2F 了**。
> 他要做的只有一件事：在导航 App 里加一段 **BLE 代码 + 一个悬浮按钮**。

---

## 一、一句话说清楚

**你的导航 App 直接连我们那两块 ESP32（蓝牙 BLE），当你走到电梯附近时，
自动在屏幕右侧冒出一个按钮，点它就真的按下了电梯的呼梯按钮；
向左拖能进一个**全屏电梯页**（轿厢现在在哪层 + 楼层键 + ▲/▼）。**

不需要中间 App，不需要服务器，**全程不需要联网**。

---

## 二、先记住这个场景（最重要）

- **一台电梯，井道 B–3F 四层**（B 在最底下）。
- **呼梯装置只装在 1F 和 2F** 两层的电梯厅（每层 1 块 ESP32，带 2 个舵机：一个按“上行”、一个按“下行”）。
  - 为什么只在中间层：真实楼里 **B 只有“上行”、3F 只有“下行”**，只有中间层才**同时有上行+下行**，才能演示上下行两种呼梯。
- 两块板广播的名字固定是 **`ELEV-1F`** 和 **`ELEV-2F`**。
- 所以：**你只会扫到 `ELEV-1F`、`ELEV-2F` 两个节点**，取 **RSSI 最大**的那个 = “用户现在在哪层”。

**核心规则（最容易搞错）**：按的是**「你当前所在的这一层」**的按钮，
**方向**由「你的目的地」决定（去高层 = 上行，去低层 = 下行）。

| 用户在哪层 | 目的地 | App 该做什么 |
|---|---|---|
| 1F | 2F / 3F | 给 **`ELEV-1F`** 写 **`UP`**（按 1F 的上行） |
| 1F | B | 给 **`ELEV-1F`** 写 **`DOWN`**（按 1F 的下行） |
| 2F | B / 1F | 给 **`ELEV-2F`** 写 **`DOWN`**（按 2F 的下行） |
| 2F | 3F | 给 **`ELEV-2F`** 写 **`UP`** |
| 1F / 2F | 同层 | 不用坐电梯 → **不显示按钮** |

> 目的地可以是 B/3F（**没装置的层也能去**）——目的地**只用来算方向**，不决定发给哪块板。

## 四、他要实现的 3 件事（= 验收点）

**① 扫描 + 判层**
- 扫描时只认名字以 `ELEV-` 开头的设备；`allowDuplicates: true` 拿持续 RSSI。
- 对每个设备做 RSSI 平滑（中位数窗口 5 + EMA α=0.5），取最大值 = `nearestFloor`。
- 用滞回防抖：`> -70 dBm` 持续 0.5s → 浮出按钮；`< -80 dBm` 持续 1.5s → 收起。

**② 算方向 + 一键呼梯**
- 从导航路线拿到 `destFloor`；用 `makePlan(current: dest:)` 算出「发给哪块板 + 上/下」（表见第二节）。
- 点按钮 → 给 `plan.callFloor` 对应的板上写 `UP`/`DOWN`。
- **成功以收到 `OK:UP`/`OK:DOWN` 通知为准**，不是“写出去就算成功”；发送中禁用按钮（防连点）。

**③ 悬浮按钮 + 向左拖进全屏电梯页**
- 按钮贴在屏幕**右侧**（`ZStack` 最上层），标 `▲ 1F` 或 `▼ 2F`。
- **点按 = 直接呼梯**；**向左拖 > 60pt = 进全屏电梯页**（就是安卓 App 主界面那一套：
  井道 + 轿厢现在在哪层 + 楼层键 + ▲/▼ + 在线状态）。
- 页面上 **`← 地图`** 或系统返回键 = 回地图。
- **「轿厢在哪层」就用你自己的蓝牙判层**：用户坐在轿厢里时，"用户在哪层"就是"轿厢在哪层"
  （装置只在 1F/2F，所以只有这两层判得出来，路过 B/3F 就保持上一次或显示 `--`，**别编数**）。
  详见 `NAV_APP_UI_SPEC.md` §10。

## 六、必须注意的坑

| 坑 | 说明 |
|---|---|
| **模拟器不行** | iOS 的 CoreBluetooth 必须**真机**，模拟器没有蓝牙。 |
| **权限声明** | `Info.plist` 必须有 `NSBluetoothAlwaysUsageDescription`，否则一调用扫描就崩。 |
| **名字在扫描响应里** | 设备名在 `advertisementData[CBAdvertisementDataLocalNameKey]`（或 `peripheral.name`）里，**别只读 `peripheral.name`**（有时为空）。 |
| **持续 RSSI** | `scanForPeripherals(..., options: [CBCentralManagerScanOptionAllowDuplicatesKey: true])`，否则同设备只回调一次、拿不到连续 RSSI。 |
| **后台会被降频** | App 进后台扫描会变慢；演示时**保持前台**（或改成“保持连接 + 定时 `peripheral.readRSSI()`”）。 |
| **回执才代表成功** | 舵机动作约 **1.3 秒**（伸出 350ms + 按住 600ms + 收回 350ms）后才发 `OK:UP`，所以按钮成功态要等通知、别写出去就报成功。 |
| **可多台手机同时用** | 每块板**最多 3 台手机**同时连；回执是广播式的，别人断开不影响你。（详见 `BLE_PROTOCOL.md` §13） |
| **别误触发** | 环境里有别的蓝牙设备，**一定**按 `name.hasPrefix("ELEV-")` 过滤。 |

## 七、联调步骤（现场）

1. 硬件上电 → 串口 115200 看到 `=== 电梯节点启动：ELEV-1F ===` 和“广播中”。
2. 先用 **nRF Connect / LightBlue** 这类 App：能看到 `ELEV-1F` / `ELEV-2F`；
   连上后往 `FFE1` 写 `UP`，应听到 1F 舵机动、并收到 `1F|OK:UP`。
3. 这一步通了，再去他的导航 App 里接同样的流程。

## 八、现场可调（不灵敏 / 太灵敏）

都在 `NAV_APP_UI_SPEC.md` §7。简单说：

- 按钮**出不来 / 太迟钝** → 浮出门槛放宽到 `-75 dBm`。
- 按钮**老误触发** → 收紧到 `-65 dBm`。
- 楼层**横跳** → 增大滞回（两门槛差拉到 12~15 dB）。
