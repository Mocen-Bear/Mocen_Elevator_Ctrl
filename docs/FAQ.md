# 常见问题（FAQ）

### 会不会出现"人还没到电梯，电梯已经在等"？

不会。整个链路里**没有任何自动触发**：App 不轮询、不按距离自动发指令，只有用户**主动点按**悬浮呼梯按钮，才会向 `FFE1` 写入 `UP` / `DOWN`。这是设计约束，不是遗漏。

### 为什么呼梯装置只装在 1F / 2F？

物理呼梯装置是自制硬件（舵机压实体按钮），成本与调试时间都集中在单台上。1F / 2F 已能覆盖主要演示动线，其余楼层靠界面指引完成体验，不做物理呼梯。

### 断网还能用吗？

能。手机与呼梯板之间是 **BLE 直连**，全程不经过公网，也不依赖任何服务器。需要联网的只有首次安装 APK 下载这一环。

### 两块呼梯板的固件差在哪？

只差 `FLOOR_NAME` 一行（`1F` / `2F`），其余完全相同。因此两份 `.ino` 文件大小一致、逻辑一致，改这一行就能互换角色。

### 舵机角度能改吗？

能，两个常量即可：松开 **70°**、按下 **130°**。改完要重新实测行程——墙面按钮的回弹距离不同，角度过大会顶住不放。保持时间（600 ms）同理，按按钮类型微调。

### APK 怎么装？

用 [`releases/android/elevator-call-v12.apk`](../releases/android/elevator-call-v12.apk) 直接安装，需要允许"安装未知来源应用"。详细步骤见 [`android/安装说明.md`](android/安装说明.md)。

### 不烧录、只用现成镜像可以吗？

可以，[`releases/firmware/`](../releases/firmware/) 下是合并好的镜像，按 [`../firmware/烧录说明.md`](../firmware/烧录说明.md) 的地址烧录即可，不需要先装 Arduino IDE。要改逻辑再走源码编译。

### 楼层判断为什么会及时"跳对"，但不会来回跳？

判层用了四层处理：**中位数滤波 → EMA 平滑 → 滞回（上下阈值不对称）→ 连胜防抖（连续 N 次同结论才提交）**。单次 RSSI 抖动不足以改变结论，因此楼层数字稳定，但人真的走过楼层边界时又能及时跟上。

### `preview/` 里那些 HTML 是什么？

是纯静态的**原型与自测页**，不需要编译、不需要服务器，浏览器直接打开即可：

| 页面 | 用途 |
|---|---|
| `index.html` | 原型总入口 |
| `elevator_ui_preview.html` | App 主界面原型 |
| `elevator_3d_model.html` / `elevator_3d_preview.html` | 3D 井道模型 |
| `ble_console.html` | BLE 指令调试台 |
| `rssi_floor_sim.html` | RSSI 判层模拟 |
| `chime_calib.html` | 到站叮声校准 |
| `floor_display_reader.html` | 楼层显示屏读数 |
| `monitor_live.html` | 实时联调监视 |
| `deck.html` / `storyboard.html` | 演示稿 |
| `teammate_app_mock.html` | 队友 App 的界面 Mock |

### `packages/` 是给谁的？

给协作方的三份独立交接包：`发给队友/`（App 对接）、`发给队友_到站检测/`（轿厢位置）、`发给队友_透视井道/`（井道模型）。每份都自带 `_版本信息.md`，可单独打包发送。

### 到站叮声节点是必须的吗？

不是。`firmware/chime_node/` 是可选的锦上添花，不装它，呼梯、判层、界面指引、3D 井道全部照常工作。

### 为什么仓库里同时有 `docs/` 和 `packages/`？

`docs/` 是项目自身的文档；`packages/` 是**按对象拆分的交接包**，内容会有重叠，但目的是"给谁就发哪一包"，避免一次性甩给对方整个仓库。
