# 交接资料包 · 版本信息

- **版本：v1.5**
- **打包日期：2026-10-18**
- 场景：一台电梯，井道 1F–4F，呼梯装置装在 **2F / 3F**（广播名 `ELEV-2F` / `ELEV-3F`）

## v1.4 → v1.5 改了什么（**只动了 `NAV_APP_UI_SPEC.md` 一句话**）

**一句话**：`NAV_APP_UI_SPEC.md` §10 原来写"我们安卓版就是这么做的，**数字下面写 `蓝牙判层`**"，
但我们安卓版 **v9 起**已经把层显框里那行小字删掉了（**框里只留一个大数字**），所以那句话**和我们对不上**了。

| 文件 | 改了什么 |
|---|---|
| `NAV_APP_UI_SPEC.md` | §10 那处更正：① 说清**我们安卓版 v9 起层显框里只有一个大数字、下面不写小字**，"这个数是判出来的还是摄像头读到的"改由**接口 `carSource`**（`near` / `camera` / `manual`）说明；② 补一句"**你那边怎么标随你**（标一行 `蓝牙判层` 也不会错），**只是别把它说成'摄像头读到的'**"。规格版本 v1.3 → **v1.4** |
| 其余 6 个文件 | **一个字没改** |

**协议一个字没改**：UUID、`UP`/`DOWN`/`ALL`/`S<n>`/`PRESS n`/`PING`/`?`/`STATUS`、回执格式（`2F|OK:UP`）、
判层的四条防抖规则、多手机上限，全都和 v1.4 一样。

> ℹ️ **和"语音"没关系**：我们安卓 App 自己那个"语音呼梯"按钮（真机上识别不准）已经在 App **v10 删除**，
> 但**那是 App 内部的功能，从来不在这个包里** —— **本包 6 份文档里一个字都没提过语音**，
> 所以这件事**不影响你要做的事**（按 `BLE_PROTOCOL.md` 写 `UP`/`DOWN` 就行）。

**用你自己的蓝牙判层就行**：用户拿着手机**坐在轿厢里**，"用户在哪层"就是"轿厢在哪层"
（装置只在 2F / 3F，所以这两层判得出来）。

## v1.2 → v1.3 改了什么（**只动了 `monitor_live.html` 一处**）

- 页面顶上那两个数字框（**甲梯 / 乙梯**）以前是"甲大乙小"，现在**一样大** ——
  本来就是**同一块厅门面板**上的两个梯，尺寸该一样。
- 顺手：两个框**永远左右并排**（就摆在两根井道的正上方），屏幕窄的时候**一起变窄**，
  不会挤出去、也不会变成上下排。
- **BLE 协议、命令、回执、`/api/status` 字段、其它 6 个文件一个字没改。**

## v1.1 → v1.2 改了什么（**只新增，原有内容一个字没删**）

- **新增 [`IOS_INTEGRATION.md`](IOS_INTEGRATION.md)**：全屏电梯页里「**轿厢现在在哪层**」怎么接。
  - 它是**走 Wi-Fi 的一个只读 JSON**：`http://<监控手机IP>:8899/api/status`，
    里面 `car` = 甲梯、`car2` = 乙梯、`carSource` = 这个数是怎么来的。
  - 含**可直接抄的 Swift 示例**（每 1.5 秒读一次）、`carSource` 三档分别该怎么显示、
    读不到就显示 `--`，以及**苹果那边必须在 `Info.plist` 开哪两个开关**
    （局域网明文 http + 本地网络权限）—— 不开就是那种"地址明明对、却怎么都连不上"。
  - 还写了怎么**整页复用我们那个真 3D 井道**。
- **新增 [`API.md`](API.md)**：安卓侧对外 HTTP 接口的完整清单（字段、示例、限制）。
- **新增 `monitor_live.html`**：**那个真 3D 井道**的现成一页 —— 和安卓 App 里那两根井道
  **同一份数学**（玻璃井壁、导轨、厅门框、呼梯面板、曳引机、对重、曳引绳、楼层标签，
  **可拖动旋转**，1F / 4F 半截暗影，轿厢连续滑动）。
  用 `WKWebView` 加载它就行，**它自己每 1.5 秒轮询**，你不用写轮询代码；
  它也能**纯当网页用**（任何浏览器打开都行）。

**BLE 协议、命令、回执、判层方式一个字没改**，照 `BLE_PROTOCOL.md` 写就行。

## 不含什么（别去问）

- **不含** ESP32 固件源码、安卓 App 源码 —— 你不需要它们，只要按 BLE 协议连上已经烧好的板子即可。
- **不含**界面预览图 —— 以 `NAV_APP_UI_SPEC.md` 的文字描述为准（要 3D 井道就直接看 `monitor_live.html`）。
- **不含** AR 3D 电梯井的模型规格 —— 那份是**单独的追加包**（`发给队友_透视井道`），
  想把井道贴到真实位置才需要。
- **不含**"用摄像头读数字"的安卓代码（**那是一条已经搁置的路**：安卓相机接口 + Kotlin 识别逻辑，
  不在这个包里）。**你现在完全不需要它** —— 轿厢楼层用自己的蓝牙判层就行。

## 怎么读

1. **`HANDOVER.md`**（5 分钟）—— 先看这份：告诉你怎么按、另外几份什么时候看，
   第五节有一段**可以直接整段复制给你自己的 AI agent** 的任务描述。
2. **`BLE_PROTOCOL.md`** —— 按电梯（蓝牙）。
3. **`NAV_APP_UI_SPEC.md`** —— 悬浮按钮 / 向左拖进全屏电梯页 / §10「轿厢在哪层」。
4. `IOS_INTEGRATION.md` / `API.md` / `monitor_live.html` —— **备选，现在不用做**（要"走 Wi-Fi 读安卓手机"时再看）。
