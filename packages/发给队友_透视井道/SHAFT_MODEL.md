# 透视电梯井：模型规格（给 iOS / ARKit 侧照抄）

> 目标：在导航 App 里把一座**半透明、发光的电梯井**叠加到真实走廊上，看起来像"透过墙看见井道"，
> 并在井道里显示轿厢位置。本文给出**和安卓 App 完全一致的几何与配色**，照抄即可两边同款。
> 版本：**追加包 v1**（独立于主资料包，不随主包版本号变化）。
> 需要和主资料包里的 `HANDOVER.md` / `BLE_PROTOCOL.md` 配套使用。

---

## 0. 先说一句最重要的（关于"真实位置"）

**现有硬件测不出真实电梯在几楼。** 那两个 ESP32 只会"按按钮"，
BLE 回执 `1F|OK:UP` 的含义是**"舵机按压动作完成"**，**不是"轿厢动了"**。电梯控制系统没有给我们任何反馈。

所以下面这张表必须分清：

| 内容 | 能不能当真数据 | 来源 |
|---|---|---|
| 井道的位置/朝向 | ✅ 真 | 你的地图节点 / 点云墙面（见 §5） |
| "你在哪一层、离井道多近" | ✅ 真 | BLE RSSI（见 `BLE_PROTOCOL.md`） |
| "哪一层的按钮被按下了、什么时候按的" | ✅ 真 | BLE 回执 `1F\|OK:UP` + 时间戳 |
| **轿厢现在在几楼** | ❌ **测不到** | 只能"推测"或加传感器（见 §6） |
| 电梯行进方向 / 还有几秒到 | ❌ 测不到 | 同上 |

**硬性要求**：只要轿厢位置是推测出来的，UI 上就**必须**有一个明确的"模拟/推测"标记。
否则有人问一句"你怎么知道电梯在 2F"，整个演示的可信度就没了。
宁可标注，也不要假装。

## 1. 坐标系约定（先定这个，后面全对得上）

- **右手系，Y 轴向上**，单位 = 米。与你项目里 `LiDARProbe` 的约定一致。
- 模型局部原点 = **井道最低楼板（B 地面）的中心**。
- **-Z = 电梯门口方向**（厅门、呼梯面板都在 -Z 面上）；+X 向右。

放进 AR 时：模型原点 → 井道的世界锚点（§5），-Z → 门口朝向（§5 的偏航角）。

## 2. 关键尺寸（全部来自安卓 `ElevatorView.kt`，照抄即可）

| 参数 | 值（米） | 含义 |
|---|---|---|
| `shaftHalf` | **0.80** | 井道内壁半宽/半深 → 井道内空 **1.6 × 1.6** |
| `carHalf` | **0.66** | 轿厢半宽/半深 → 轿厢 **1.32 × 1.32**（只留 0.14 安装间隙，故意"塞满"） |
| `carHalfH` | **1.05** | 轿厢半高 → 轿厢高 **2.10**（≈ 层高） |
| `floorGap` | **2.60** | 层高 |
| `carClear` | **0.06** | 轿厢底距楼板 |
| `pitDepth` | **0.45** | 底坑（最低楼板以下） |
| `headroom` | **1.00** | 顶层之上净空（放曳引机） |
| `slabBorder` | **0.11** | 楼板"贴墙窄环"的宽度 |

由此推出的三个换算（**直接决定轿厢在哪一层**）：

```text
slabY(i)      = i * 2.60                  // 第 i 层楼板高度（i=0 是 B）
carCenterY(i) = slabY(i) + 1.11           // 轿厢中心高度（= 1.05 + 0.06）
doorH()       = 1.05*2 - 0.18 = 1.92      // 厅门净高
shaftBottom   = slabY(0) - 0.45 = -0.45
shaftTop      = carCenterY(3) + 1.05 + 1.00 = 10.96
```

> 层号 ↔ 下标：`B=0, 1F=1, 2F=2, 3F=3`。
> 本项目**只做 1F / 2F**（那两层才有装置）：轿厢只能出现在 `carCenterY(1)=3.71` 或 `carCenterY(2)=6.31`。

```text
cwY = (shaftTop-0.75) + t * ((shaftBottom+0.85) - (shaftTop-0.75))
```

## 4. "透视 / 全息"怎么出效果（这是重点，几何很简单，材质才是关键）

**好消息：ARKit 默认没有遮挡关系**——你放进去的 3D 内容永远画在真实画面**上面**。
所以"透过墙看见井道"**不需要任何特殊技术**，默认就长这样。要做的只是让它像"发光体"而不是"实心玩具"：

1. **不用受光材质**。玻璃、门板、井壁一律 `lightingModel = .constant`（SceneKit）/ `UnlitMaterial`（RealityKit），
   只吃颜色和自发光，不吃场景灯光——否则跟真实光照一比就"假"。
2. **半透明 + 关闭写深度**：
   `transparency ≈ 0.13~0.25`、`writesToDepthBuffer = false`、`readsFromDepthBuffer = false`，
   然后靠"从后往前"排序绘制（或直接开打通混合）。不写深度就能自然叠加，不会互相挖洞。
3. **边缘辉光**：把线框（顶圈梁/立柱/腰线/导轨）单独画一遍，再**复制一份放大 1.02~1.05 倍**、
   用 `blendMode = .add`（加法混合）叠上去 → 立刻有"霓虹管"感。
4. **扫描线/能量流**：给井壁加一个 fragment shader modifier，让一条水平的亮带以约 0.15 屏/秒向上移动，
   或者做 `sin(worldY*2 - time*2)` 的呼吸条纹 → 全息感。成本极低，观感提升最大。
5. **楼层数字**：`SCNBillboardConstraint`（永远朝向相机），或 RealityKit 的 `Billboard` 组件。
   字号建议 ≥ 屏高的 3%，颜色 `#C6DCF0` + 轻微自发光。
6. **被呼的楼层要亮起来**：收到 `1F|OK:UP` 后，把 1F 的门框/腰线/按钮灯调成 `#7CE0A0` 并加脉冲。
   **这是全局最"真"的一处反馈**（真的发生了），一定要做。
7. **可选**：如果想让它更像"嵌在墙里"，用 `sceneDepth` 对井道做一个深度淡出（离墙近的地方更淡）。
   但这属于加分项，不做也完全能看。

## 5. 井道锚在哪里、朝向怎么定

按"省事 → 炸裂"排：

1. **人工锚点（最稳，推荐先做）**：建图时站在电梯门口，在路网里标一个节点，
   记录位置 + 门口朝向（人朝门站的朝向你已经有了）。井道就放在这个节点上。
2. **用点云自动对齐**：从该节点附近的 LiDAR 点云拟合出墙面平面法向，
   把井道的 -Z 面正对该法向 → 朝向自动、不用手工调角。
3. **用 RSSI + AR 位姿反推信标位置（最炸）**：你一边走，App 一边记录
   "AR 相机位姿 ←→ `ELEV-1F`/`ELEV-2F` 的 RSSI"。同一位置多组观测就能反解出
   **ESP32 在世界坐标里的位置**——井道会自动"长"在正确的地方，零手工标点。
   本质是"拿手机当探针，给信标定位"。
   （注意：RSSI 抖动大，需要多帧平均 + 只在近距离用；解出来只是米级，够把井道放在对的位置。）

## 6. 轿厢位置：三种来源，必须二选一并标注

| 方案 | 真实性 | 成本 | 说明 |
|---|---|---|---|
| **A. 推测动画** | ❌ 模拟 | 0 | 收到 `OK:UP` 后按经验时间演一段升降。**UI 必须标"模拟"** |
| **B. 听"叮"声**（推荐） | ✅ 真数据 | ~10 元/层 | 电梯到站有铃声。1F/2F 各加一个麦克风模块，ESP32 检测到铃声 → 通过 BLE 播一条 `CAR\|1F`。**"车现在在 1F"就是真的** |
| **C. 光敏看按钮灯** | ✅ 真数据 | ~2 元/层 | 呼梯按钮自己那盏灯：按下亮、到站灭。但可能被舵机臂挡住视线，需现场试 |

- 选 **A**：井道里轿厢的移动曲线请写"约 1 层/2 秒"并加重启复位，别做成匀速科幻电梯。
- 选 **B**：协议要加一节（我们这边改固件 + 文档），你收到 `CAR|xF` 就设轿厢目标层。
  注意它给的是**"哪一层"而不是"离这层还有几米"**，够用了。

## 7. 可选：只做 1F / 2F 的"视野窗口"

安卓那边的做法是**不把 B–3F 全塞进一屏**，而是只框住 1F / 2F、上下各露半截：

```text
viewBottom = slabY(1) - 1.00            = 1.60
viewTop    = slabY(3) + 0.80            = 8.60      // 注意是 slabY(i1+1)
viewHeight = 7.00
band = [slabY(1), slabY(3)] = [2.60, 7.80]          // 带外的几何做"虚影"
虚影：不透明度 ×0.26，亮度 ×0.62
上下渐隐：顶部/底部各 22% 高度，0.82 不透明的深色渐变（#03070C）
```

效果：井道看起来**大一倍**，1F/2F 完整，B/3F 只剩半截、融进黑暗里。
AR 里比这个更自由（人本来就站在井道边上），**建议 AR 直接做全高**，只在
"手机竖屏小面板"那种视图里用这套窗口。

## 8. 验收清单（照着勾）

- [ ] 井道出现在电梯厅的真实位置、门口朝向对（人对着门站，门在正前方）
- [ ] 井道半透明、能看见后面的真实墙面；线框有发光边缘
- [ ] 楼层数字永远朝向相机、1F/2F 可读
- [ ] 收到 `1F|OK:UP` 后，**1F 那一层亮起**（真数据反馈）
- [ ] 轿厢停在 1F/2F 之一；若为推测，**界面上有"模拟"标记**
- [ ] 走远（RSSI 低于阈值）后井道/按钮的显隐符合 `NAV_APP_UI_SPEC.md`
- [ ] 手机发烫/掉帧可接受（半透明多面体在手机上很吃带宽，别做太密的网格）

## 9. 附录：想用 2D 叠加（不用 3D 引擎）时的投影公式

如果你的 `RouteRenderer` 是 2D 覆盖层，不想上 SceneKit，那么**用同一套数学**也能画出来——
这就是安卓和 `preview/elevator_3d_preview.html` 里跑的那套，已经验证可用：

```text
DIST = 9.0, NEAR = 0.15
yaw = 0.42, pitch = -0.13                   // 初始朝向（可拖动改）

// 世界点 (x,y,z) → 屏幕
yy   = y - viewCenterY                       // viewCenterY = (viewBottom+viewTop)/2
rx   =  x*cos(yaw) + z*sin(yaw)
rz0  = -x*sin(yaw) + z*cos(yaw)
ry   = yy*cos(pitch) - rz0*sin(pitch)
rz   = yy*sin(pitch) + rz0*cos(pitch) + DIST
s    = focal / max(rz, NEAR)                 // focal = 0.96 * H / viewHeight
screenX = W/2 + rx*s ,  screenY = H/2 - ry*s

// 面亮度（平面着色，和 3D 版一致）
亮度 = 0.34 + 0.66 * |N·L| ,  L = normalize(0.40, 0.80, 0.45)
// 按面平均 depth = rz 从大到小排序，再依次填充 = 画家算法
```

（AR 里当然更该用真正的 3D：把同样的顶点喂给 SceneKit/RealityKit，让 ARKit 管相机位姿。）
