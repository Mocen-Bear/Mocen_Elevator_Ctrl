④ 摄像头读电梯楼层显示 ⚠️ 这条路现已搁置 · 留作原型/备用

三种模式：离线自测（当场出准确率：单帧 84~89% 读对、0~2% 读错，其余输出"未识别"）· 上传现场照片（出门前拍的那张）· 摄像头实时。 关键：宁可说"没看清"，也绝不猜；实时要连续 3 帧一致才采纳。
现在演示用的是蓝牙判层（你拿着手机坐在轿厢里，靠近哪层显示哪层）；这一页留作"原理可讲"的原型。

打开 ▸

⑤ 楼层判定仿真 / 现场调参 被问"会不会乱跳"时用

把 App 里的判定算法逐行搬进网页，配室内传播模型 + 噪声跑： 站在某层装置旁 20 s 0 次抖动（首判 200 ms）；站在两层正中间朴素做法横跳 25.7 次， 我们的算法 4.3 次，换成推荐现场参数（4.5 dB / 连赢 2）只剩 1.3 次。
页面上三个按钮 = 三组对照实验；也可以直接拖"我"的位置、拖参数看判定怎么变。

打开 ▸

⑥ 到站"叮"声标定台 只有装了到站检测节点才用

把固件里那套 DSP（4 kHz 采样 → 40 ms 窗口 → RMS + 过零率）原样搬到网页， 用麦克风边听边出数，最后直接给出能粘回 chime_node.ino 的 #define 那几行。
先点「离线自测」（不用麦克风）验证逻辑：静音 0 次、1200 Hz"叮"报 1 次且频率读回 1200、 400 Hz 强音 0 次、宽带噪声会命中（已标注为已知边界）。
它今晚抓出过一个真 bug：固件里过零只数上升沿、却用了"上下沿"的公式，频率被算小一半 —— 已修。

打开 ▸

⑦ 现场蓝牙控制台 备用 / 调试 · 手机出问题时用

手机 App 扫不到装置时，用笔记本 Chrome 打开这一页：选 ELEV-1F（或 ELEV-2F）→ 点 UP/DOWN 直接呼梯， 回执（1F|OK:UP）实时出现在页面上；也能连 CHIME-1F 看它报不报 CAR:CHIME（现场标"叮"声用）。
和固件的 UUID / 命令逐字一致（已用脚本比对过）。页面的协议速查表把两条协议都印在里面，走廊里不用翻文档。它没有任何定时器，不会自动发命令。

打开 ▸

⑧ 队友导航 App 最终页面（模拟） 看"效果"时用 · 也能给队友看

把队友那个 iOS 导航 App 最后的样子用网页照做了一份：顶部大字「电梯现在在几层」、 右侧绿钮「点 = 呼梯 / 按住向左拖 = 进全屏电梯页」、底部一排模拟开关（你在 / 要去 / 甲梯 / 乙梯）。手机上打开也能用。
它和安卓 App 里新加的那一页（NavMockActivity）是同一套尺寸、同一套逻辑， 已逐条核对：判方向、呼叫 → 回执 → 轿厢开过来、全屏页不越界、两台轿厢各走各的。
全屏页里是两台电梯：甲梯跟着你走（你在哪层它就在哪层）、到站自动开门（停一会儿再关）； 乙梯是纯装饰，B~3F 随机慢慢跑（两台层显一样大、各占一半、正好压在各自井道正上方， 框里只有大数字、底下不写小字）。 真机上「电梯在哪层」用的是自己的蓝牙判层。
数据全是模拟的（页面上都标了"模拟"），不连蓝牙；呼梯来自蓝牙（真机上）。

打开 ▸

注意事项
· 这些页面都是**纯前端**，不联网也能跑；但 floor_display_reader.html 的"摄像头实时"和任何 getUserMedia 都要求安全上下文：localhost 可以，http://局域网IP 会被浏览器拦掉 （用 chrome://flags/#unsafely-treat-insecure-origin-as-secure 可以临时放行，仅用于提前试）。 · ble_console.html（⑦）用 Web 蓝牙，同样要求安全上下文，而且双击本地文件常被浏览器直接拒绝 —— 请用 http://localhost:8777/ble_console.html 打开；页面顶部也会自己检测并把解决办法写出来。 · 演示当天只依赖 ①：它不需要摄像头、不需要网络、不需要硬件。 · 要发给队友的资料在 packages/（发给队友/、发给队友_透视井道/、发给队友_到站检测/）， 这一页不负责那些。 · 两块板子的成品固件在 releases/firmware/；手机 App 按 docs/android/安装说明.md 自行构建。
